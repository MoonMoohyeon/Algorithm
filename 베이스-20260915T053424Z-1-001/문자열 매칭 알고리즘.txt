주어진 문자열 str
찾고자 하는 문자열 fin 
이라하자

str에 대해 fin을 무식한 방법으로 찾는다고하자
for(int i=0; i<N; i++){
	if(str[i] == fin[0]){
		// 있는지 검사
	}
}

위 방법으로 진행할 경우, 부분적 불일치가 생기면 바로 다음 검색을 '처음부터'수행 한다.
이는 이전 탐색의 fin과 str 부분의 '초기 일치함 정도'의 낭비라고 볼 수 있다.

<< 이 때 초기 일치함 정도에서 접두사 == 접미사  부분을 사용하면 탐색범위를 크게 줄일 수 있다.
ex)
ABCDABCDEE == str
ABCDABCE == fin이라 하자
fin은 i=0에 대해
ABCDABC 까지 일치한다. 하지만 마지막E에서 일치하지 않는다.

일치한 문자열 ABCDABC에서 접미사 접두사 == 3 이다. 'ABC'D'ABC'
따라서 다음 문자열 탐색을 할때. 불일치한 부분 idx - 3부터 재검색 하면 된다.

이를 idx-(접두사 == 접미사 개수)으로 볼 수 있다.

보통 접구사 == 접미사 개수은 table화하여 미리 전처리한다. 
ex) fin = ABCDABCE라 할때
p[0] = "" = 0
p[1] = "A" = 0
p[2] = "AB" = 0
p[3] = "ABC" = 0
p[4] = "ABCD" = 0
p[5] = "ABCDA" = 1
p[6] = "ABCDAB" = 2
p[7] = "ABCDABC" = 3
p[8] = 전부일치 << 따라서 0 ~7까지만 생각한다.
